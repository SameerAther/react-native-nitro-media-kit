# 0.5.0 versus current changes — 23 October 2026

All executed checks passed in both versions. No video export speedup was measured. CPU planning costs increased as the options structure and validation expanded; the absolute cost remains below one microsecond per plan in this host benchmark.

Before: `v0.5.0`, commit `7047c095231e79994b9a2326c9e999432168f8d5`. After: uncommitted working tree based on that commit. Production source and harness SHA-256 hashes are recorded in [raw results](2026-10-23-apple-m2.json).

Host: Apple M2, 8 GiB RAM, macOS 26.6, Swift 6.2.3. Both variants compiled with `-O -whole-module-optimization`. Ten alternating run pairs, 500,000 operations per case per run and 10,000 warmup operations per case. All seven plan outputs and checksums matched exactly across both versions. Other tests and builds were idle during measurement. OS scheduling and thermal state were not explicitly controlled.

Medians describe planning, which now performs additional validation. They exclude media resolution, decoding, encoding, file I/O and bridge calls. Watermark validation also checks text and style bounds in the new planner. These are different amounts of validation work producing the same plan; a percentage increase here is not an equivalent increase in whole-export time. The harness uses each revision’s host boundary types, so the expanded options layout is also part of the measured difference.

Median peak RSS of the entire planner benchmark process: 6.03 MiB before, 6.09 MiB after (+64 KiB). This includes the harness and runtime, and excludes app, codec and GPU allocations.

The new loudness analyzer has no 0.5.0 equivalent. Five independent host runs per case measured production DSP over a reused 100 ms PCM buffer; initialization and final gating are included, while sample generation and decoding are excluded.

For a separate three-second 1 kHz stereo fixture at 48 kHz and −20 dBFS, the Swift analyzer measured -19.9933 LUFS and -20.0000 dBTP. FFmpeg ebur128 reported −20.0 LUFS and −20.0 dBFS true peak, matching to its displayed 0.1-unit precision. This single fixture is a reference check, not a complete loudness compliance suite.

Test counts and suite durations are not throughput benchmarks. Type checking and ESLint produced no errors; ESLint reported stale Browserslist data. Gradle reported existing deprecation warnings. Details are saved in [test results](2026-10-23-tests.json).

No UI, simulator or emulator runtime tests were executed. No physical Android device was connected; the paired iPad was unavailable. The iOS build compiled against the simulator SDK without launching a simulator. Offline validator tests exercise synthetic good/bad fixtures, including intermittent watermark flicker, rather than outputs from either native pipeline.

Unmeasured: native video export latency/throughput, batch-thumbnail speedup, metadata reuse savings, app memory, energy, HDR output fidelity, audiovisual sync and exported-frame flicker. These require identical physical-device runs before and after. No claim about those improvements follows from these host timings.
